# Категории

Credo Statement Analyzer автоматически категоризирует расходные транзакции с помощью системы правил на основе 91 регулярного выражения.

### Как работает категоризация

Для каждой транзакции текст `operation + " " + description` проверяется по упорядоченному списку regex-правил. **Первое совпавшее правило** определяет категорию.

```
Input:  "გადახდა - SPAR 18.39 GEL 31.07.2025"
Match:  /SPAR/i → Продукты
Result: { name: "Grocery", icon: "🛒" }
```

Если ни одно правило не совпало, транзакция категоризируется как **Другое** (📦).

#### Производительность

Результаты категоризации кэшируются с помощью `WeakMap`, где ключом является ссылка на объект транзакции. Поскольку категоризация вызывается многократно для каждой транзакции (в сводках, графиках, таблицах, аналитике), кэш устраняет избыточное сопоставление регулярных выражений — обычно экономя более 250 000 regex-проверок для набора данных из 500 транзакций.

### Обнаружение внутренних переводов

Две категории рассматриваются как «внутренние переводы» и отфильтровываются при активном **фильтре шума**:

- **Обмен валюты** (💱)
- **Перевод себе** (🔄)

Это предотвращает завышение итогов доходов и расходов из-за внутренних перемещений средств.

### Извлечение названия продавца

При формировании разбивки по категориям и списков продавцов приложение извлекает читаемое название продавца с помощью следующих паттернов (по порядку):

1. **Оплата картой**: `გადახდა - MERCHANT_NAME 18.39 GEL` → `MERCHANT_NAME`
2. **Оплата коммунальных услуг**: `გაზი - სოკარ ჯორჯია გაზი - 003102794156` → `სოკარ ჯორჯია`
3. **Имя получателя**: `transaction.beneficiaryName`, если доступно
4. **Запасной вариант**: `transaction.operation` или `transaction.description`
