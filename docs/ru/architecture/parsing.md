# Конвейер парсинга

На этой странице описано, как Credo Statement Analyzer преобразует исходные банковские файлы в структурированные объекты транзакций.

### Обзор

```
File (.xlsx / .pdf / .csv)
    |
    v
detectFileType(extension)
    |
    ├── .xlsx → parseXLSX()
    ├── .pdf  → parsePDF()
    └── .csv  → parseCSVFile()
    |
    v
Normalized Transaction Objects
    |
    v
Currency stamping (from accountInfo / filename / default)
    |
    v
Chronological sort
```

### Парсер XLSX

#### Определение листа

Парсер сканирует имена всех листов в рабочей книге и ищет:

| Тип листа | Совпадающие имена |
|-----------|-------------------|
| Транзакции | Содержит `"transaction"` (EN) или `"ტრანზაქცი"` (GE) |
| Данные счёта | Содержит `"account"`, `"detail"` (EN) или `"დეტალები"` (GE) |

Если лист транзакций не найден, в качестве запасного варианта используется **последний лист** рабочей книги.

#### Конвейер преобразования

1. Чтение файла Excel как `Uint8Array` с помощью `FileReader`
2. Парсинг через SheetJS: `XLSX.read(data, { type: 'array', cellDates: true })`
3. Преобразование в строку CSV: `XLSX.utils.sheet_to_csv(sheet, { dateNF: 'yyyy/mm/dd' })`
4. Парсинг строки CSV внутренней функцией `parseCSV()`

#### Извлечение информации о счёте

Из листа данных счёта считываются пары ключ-значение (столбец A = ключ, столбец B = значение). Грузинские ключи сопоставляются с английскими:

| Грузинский | Английский |
|------------|------------|
| ანგარიშის მფლობელი | Account Holder |
| საიდენტიფიკაციო ნომერი | Identification Number |
| ამონაწერის პერიოდი | Statement Period |
| ანგარიშის ნომერი | Account Number |
| ანგარიშის ვალუტა | Account Currency |
| საწყისი ნაშთი | Opening Balance |
| საბოლოო ნაშთი | Closing Balance |

### Парсер PDF

#### Определение формата

Парсер читает текст страницы 1 и проверяет наличие `"Account Statement"` или `"ამონაწერი"`. Это определяет тип файла:

- **Полная выписка** → `parsePDFStatement()` — многостраничная таблица транзакций
- **Платёжная квитанция** → `parsePDFReceipt()` — документ с одной транзакцией

#### Парсинг полной выписки

Это самый сложный парсер. Он восстанавливает таблицу из позиционированных текстовых элементов.

##### Шаг 1: Извлечение текстовых элементов

С помощью `pdfjs-dist` каждая страница обрабатывается для извлечения текстовых элементов с их позицией:

```javascript
{
    str: "318.58",     // the text content
    x: 245,            // horizontal position (pixels from left)
    y: 382,            // vertical position (pixels from bottom)
    page: 1            // page number
}
```

##### Шаг 2: Определение границ столбцов

Парсер сканирует страницу 1 в поисках текста заголовков (например, "Date", "Turnover (DB)", "Balance") и записывает их X-координаты. Границы столбцов устанавливаются посередине между соседними заголовками.

| Столбец | Левая граница | Правая граница |
|---------|---------------|----------------|
| Date | 0 | mid(Date, Operation) |
| Operation | mid(Date, Op) | mid(Op, Debit) |
| Debit | mid(Op, DB) | mid(DB, Credit) |
| Credit | mid(DB, CR) | mid(CR, Balance) |
| Balance | mid(CR, Bal) | mid(Bal, Description) |
| Description | mid(Bal, Desc) | mid(Desc, BenefName) |
| Beneficiary Name | mid(Desc, BName) | mid(BName, BAccount) |
| Beneficiary Account | mid(BName, BAcc) | правый край страницы |

Если заголовки не найдены (например, выписка только на грузинском), используются жёстко заданные границы по умолчанию.

!!! info "Обработка разделённых заголовков"
    Некоторые заголовки состоят из двух текстовых элементов PDF (например, `"Turnover"` + `"(DB)"` как отдельные элементы). Парсер обрабатывает это, выполняя поиск ближайших элементов в пределах 80px по горизонтали на той же линии Y.

##### Шаг 3: Определение начала строк

Строка начинается там, где паттерн даты `DD.MM.YYYY` появляется при x < DATE_MAX. Все элементы между последовательными началами строк назначаются этой строке.

##### Шаг 4: Назначение элементов столбцам

Для каждой строки элементы распределяются по столбцам на основе их X-позиции относительно определённых границ. Текстовые элементы заголовков предварительно отфильтровываются.

##### Шаг 5: Построение объектов транзакций

- Дата: преобразуется из `DD.MM.YYYY` в `YYYY/MM/DD`
- Дебет/Кредит/Баланс: извлекаются с помощью сопоставления денежных паттернов (`/^\d+\.\d{2}$/`)
- Описание и получатель: объединяются из всех текстовых элементов соответствующих столбцов

#### Парсинг платёжной квитанции

Более простой парсер на основе регулярных выражений, который извлекает:

- Дату операции: из паттерна `"Operation Date YYYY-MM-DD"`
- Сумму: из паттерна `"Amount: 1,234.56 GEL"`
- Детали: из паттерна `"Operation Details: ..."`
- Получателя: имя и номер счёта из соответствующих полей

Квитанции всегда формируют одну расходную транзакцию.

### Парсер CSV

#### Структура

CSV-файлы Credo Bank содержат:

1. **Секция заголовка** — пары ключ-значение (информация о счёте) перед строками данных
2. **Строка заголовков столбцов** — обычно `Date, Operation, Turnover (DB), Turnover (Cr), Balance, Description, ...`
3. **Строки данных** — по одной на транзакцию

#### Правила парсинга

| Проблема | Решение |
|----------|---------|
| Запятая внутри чисел | Поля в кавычках: `"1,220.09"` — парсер учитывает границы кавычек |
| Многострочные описания | Если строка не начинается с `YYYY/`, она добавляется к операции предыдущей транзакции |
| Незакрытые кавычки | Строки объединяются, пока количество кавычек не станет чётным |
| Грузинские заголовки | Сопоставляются с английскими через ту же таблицу ключей, что и для XLSX |

#### Парсинг сумм

Все суммы проходят через:

```javascript
function parseAmount(str) {
    const cleaned = str.replace(/,/g, '').trim();
    const num = parseFloat(cleaned);
    return isNaN(num) ? 0 : num;
}
```

Обработка: `"1,220.09"` → `1220.09`, `""` → `0`, `"abc"` → `0`.

### Объединение нескольких файлов

При одновременной загрузке нескольких файлов через `parseFiles()`:

1. Каждый файл парсится независимо
2. Валюта определяется для каждого файла (accountInfo > имя файла > значение по умолчанию)
3. Все транзакции помечаются своей валютой
4. Транзакции из всех файлов объединяются
5. Объединённый массив сортируется по дате по возрастанию
6. Все объекты информации о счетах собираются

#### Добавление файлов позже

При использовании кнопки "+ Add Files" из панели управления выполняется этап дедупликации:

```javascript
const makeKey = (tx) =>
    `${tx.date}|${tx.debit}|${tx.credit}|${tx.operation}|${tx.currency}|${tx.balance}`;

const existingKeys = new Set(existingTransactions.map(makeKey));
const newTx = parsedTransactions.filter(tx => !existingKeys.has(makeKey(tx)));
```

Это предотвращает дублирование при повторной загрузке файлов, которые пересекаются с существующими данными.

### Определение валюты из имени файла

Если лист информации о счёте не указывает валюту, парсер пытается определить её из имени файла:

| Паттерн | Регулярное выражение |
|---------|----------------------|
| `_GEL_`, `_USD_` | `/_(\w+)_/i` |
| `.GEL.`, `.USD.` | `/[._-](\w+)[._-]/i` |
| `GEL.xlsx` | `/(\w+)\.(PDF\|XLSX?\|CSV)/i` |
| `STATEMENT_USD` | `/STATEMENT[._-](\w+)/i` |
| `GEL STATEMENT` | `/(\w+)\s*STATEMENT/i` |

Поддерживаемые валюты: GEL, USD, EUR, RUB, GBP.
