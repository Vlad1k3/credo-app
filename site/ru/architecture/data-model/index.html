    Модель данных¶

    На этой странице описаны внутренние структуры данных, используемые в Credo Statement Analyzer.

    Объект транзакции¶

    Каждая транзакция в системе имеет следующую структуру:

    Поле Тип Описание Пример
    date string Дата в формате YYYY/MM/DD "2025/07/14"
    operation string Тип операции (на грузинском или английском) "გადახდა"
    debit number Сумма расхода (0, если доход) 18.39
    credit number Сумма дохода (0, если расход) 0
    balance number Баланс счёта после этой транзакции 1542.67
    description string Полное описание транзакции "გადახდა - SPAR 18.39 GEL"
    beneficiaryName string Имя получателя "SPAR GEORGIA"
    beneficiaryAccount string IBAN получателя "GE12CD..."
    type string "income" или "expense" "expense"
    amount number Абсолютная сумма транзакции 18.39
    currency string Код валюты по ISO 4217 "GEL"

    Производные поля (после конвертации валюты)¶

    При конвертации транзакций в валюту отображения появляются два дополнительных поля:

    Поле Тип Описание
    originalCurrency string Валюта до конвертации
    currency string Обновляется на валюту отображения

    Поля debit, credit, balance и amount заменяются конвертированными значениями.

    Ключевые инварианты¶

    • Каждая транзакция имеет ровно одно из debit > 0 или credit > 0 (никогда оба одновременно)
    • type === "income" тогда и только тогда, когда credit > 0
    • amount === (type === "income" ? credit : debit)
    • date всегда в формате YYYY/MM/DD, что делает строковое сравнение эквивалентным хронологическому порядку
    • Транзакции всегда отсортированы по date по возрастанию

    Объект информации о счёте¶

    Извлекается из листа/заголовка данных счёта каждого загруженного файла:

    Поле Тип Описание Пример
    Account Holder string Имя владельца счёта "JOHN DOE"
    Account Number string IBAN или номер счёта "GE12CD0360000012345678"
    Account Currency string Код по ISO 4217 "GEL"
    Opening Balance string Баланс на начало периода выписки "1200.00"
    Closing Balance string Баланс на конец периода выписки "1542.67"
    Statement Period string Диапазон дат выписки "01.01.2025-31.01.2025"
    Identification Number string Личный идентификационный номер "01234567890"

    Note

    Наличие всех полей не гарантировано. Из PDF-выписок может быть извлечено только подмножество полей. Значения Opening/Closing Balance являются строками и могут содержать запятые.

    Формат хранения¶

    Данные сохраняются в localStorage в формате JSON:

    {
  "transactions": [
    {
      "date": "2025/07/14",
      "operation": "გადახდა",
      "debit": 18.39,
      "credit": 0,
      "balance": 1542.67,
      "description": "გადახდა - SPAR 18.39 GEL 14.07.2025",
      "beneficiaryName": "",
      "beneficiaryAccount": "",
      "type": "expense",
      "amount": 18.39,
      "currency": "GEL"
    }
  ],
  "accountInfos": [
    {
      "Account Holder": "JOHN DOE",
      "Account Number": "GE12CD0360000012345678",
      "Account Currency": "GEL",
      "Closing Balance": "1542.67"
    }
  ]
}

    Ключ хранилища: credo_statement_data

    Обратная совместимость¶

    Старые версии хранили только массив транзакций (без объекта-обёртки). Загрузчик обрабатывает это:

    if (Array.isArray(parsed)) {
    result = { transactions: parsed, accountInfos: [] };
}

    Транзакции без поля currency автоматически помечаются значением "GEL".

    Кэш обменных курсов¶

    Хранится отдельно в localStorage:

    {
  "2025/07/14": {
    "USD": { "rate": 2.6856, "quantity": 1 },
    "EUR": { "rate": 2.9123, "quantity": 1 }
  }
}

    Ключ хранилища: credo_nbg_rates

    Ключи периодов¶

    Приложение использует строковые ключи периодов для фильтрации и навигации:

    Период Формат ключа Пример
    День YYYY/MM/DD "2025/07/14"
    Неделя YYYY/MM/DD (понедельник) "2025/07/14"
    Месяц YYYY/MM "2025/07"
    Год YYYY "2025"

    Все ключи сортируются лексикографически, что делает хронологическую сортировку тривиальной (keys.sort()).

    Результат категоризации¶

    Результат выполнения функции categorize():

    { name: "Grocery", icon: "🛒" }

    Результаты кэшируются в WeakMap с ключом по ссылке на объект транзакции, поэтому повторные вызовы для одного и того же объекта транзакции возвращают результат мгновенно.

    Объект сводки¶

    Результат выполнения calculateSummary():

    Поле Тип Описание
    totalIncome number Сумма всех кредитов (доходов)
    totalExpense number Сумма всех дебетов (расходов)
    net number Доходы - Расходы
    avgDailyExpense number Расходы / уникальные дни
    avgDailyIncome number Доходы / уникальные дни
    avgMonthlyExpense number Расходы / уникальные месяцы
    avgMonthlyIncome number Доходы / уникальные месяцы
    startingBalance number Восстановленный начальный баланс
    currentBalance number Баланс последней транзакции
    totalTransactions number Количество транзакций
    numDays number Уникальные дни с транзакциями
    numMonths number Уникальные месяцы с транзакциями
    currencies string[] Обнаруженные валюты
    isMultiCurrency boolean Более одной валюты
    dateRange object { from: "YYYY/MM/DD", to: "YYYY/MM/DD" }
    commonAdjustment number? Сверка с закрывающим балансом (при необходимости)
