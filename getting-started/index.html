    Upload & Setup

    Upload & Setup¶

    Supported File Formats¶

    Credo Statement Analyzer accepts three file types exported from Credo Bank:

    XLSX (Excel) — Recommended¶

    The richest format. The parser looks for two sheets:

    • Account Details (or "დეტალები") — account holder, account number, currency, opening/closing balance
    • Transactions (or "ტრანზაქცი") — the transaction table

    If these sheet names aren't found, the parser falls back to the last sheet in the workbook.

    PDF¶

    Two PDF formats are supported:

    1. Full Account Statement — multi-page table with columns: Date, Operation, Debit, Credit, Balance, Description, Beneficiary. Detected by the presence of "Account Statement" or "ამონაწერი" in the header.
    2. Payment Order Receipt — single-transaction receipt. The parser extracts date, amount, operation details, and receiver/sender info.

    How PDF parsing works

    The parser uses pdfjs-dist to extract text items with their X/Y positions from each page. It dynamically detects column boundaries from header positions (e.g., "Turnover (DB)", "Balance", "Description") and assigns text items to columns based on their X coordinate. Date entries (DD.MM.YYYY at x < 100) mark row starts.

    CSV¶

    Plain text comma-separated format. The parser:

    1. Extracts account info from header lines (before the first data row)
    2. Handles quoted fields with embedded commas (e.g., "1,220.09")
    3. Handles multiline descriptions (lines not starting with a date are appended to the previous row)
    4. Translates Georgian header keys to English automatically

    How to Upload¶

    1. Drag & Drop — drag file(s) from your file explorer onto the upload zone
    2. Click to Browse — click the upload button and select files

    Multiple files

    You can upload multiple files at once. The app automatically merges and deduplicates transactions across files. This works for:

    • Multiple months of the same account
    • Different accounts (GEL + USD)
    • Mixed formats (some XLSX, some PDF)

    Currency Detection¶

    The app determines each file's currency through this priority chain:

    1. Account Info sheet — Account Currency field from XLSX/CSV headers
    2. Filename pattern — detects currency codes in filenames like MYCREDO_GEL_STATEMENT_... or statement_USD.pdf
    3. Default — falls back to GEL

    Supported filename patterns:

    Pattern Example
    _GEL_ MYCREDO_GEL_STATEMENT_2025.xlsx
    .USD. statement.USD.pdf
    -EUR- export-EUR-jan.csv
    GEL.xlsx GEL.xlsx
    STATEMENT_USD STATEMENT_USD.pdf

    Deduplication¶

    When adding files to an existing dataset (via the "+ Add Files" button), the app prevents duplicate transactions using a composite key:

    key = date | debit | credit | operation | currency | balance

    Only transactions whose key doesn't already exist are added. This means you can safely re-upload overlapping files without getting duplicates.

    Data Storage¶

    Parsed data is stored in the browser's localStorage under the key credo_statement_data. This means:

    • Data persists across page refreshes and browser restarts
    • Data is scoped to the browser and origin (not shared across devices)
    • Clearing browser data or clicking "New File" removes everything

    Storage limits

    localStorage has a ~5 MB limit in most browsers. For very large datasets (thousands of transactions across many accounts), you may approach this limit. The app handles quota errors gracefully — if it can't save, it will continue working from memory.

    Offline Usage¶

    After the first page load, the app works fully offline. To verify:

    1. Open the app and load it once
    2. Disconnect from the internet
    3. Upload a bank statement
    4. The dashboard will load and function normally

    The only feature that requires internet is exchange rate fetching for multi-currency accounts (from the NBG API).

    Загрузка и настройка¶

    Поддерживаемые форматы файлов¶

    Credo Statement Analyzer принимает три типа файлов, экспортированных из Credo Bank:

    XLSX (Excel) — Рекомендуемый¶

    Наиболее полный формат. Парсер ищет два листа:

    • Account Details (или «დეტალები») — владелец счёта, номер счёта, валюта, начальный/конечный баланс
    • Transactions (или «ტრანზაქცი») — таблица транзакций

    Если эти названия листов не найдены, парсер использует последний лист в книге.

    PDF¶

    Поддерживаются два формата PDF:

    1. Полная выписка по счёту — многостраничная таблица со столбцами: Дата, Операция, Дебет, Кредит, Баланс, Описание, Бенефициар. Определяется по наличию «Account Statement» или «ამონაწერი» в заголовке.
    2. Квитанция платёжного поручения — квитанция по одной транзакции. Парсер извлекает дату, сумму, детали операции и информацию о получателе/отправителе.

    Как работает парсинг PDF

    Парсер использует pdfjs-dist для извлечения текстовых элементов с их координатами X/Y с каждой страницы. Он динамически определяет границы столбцов по позициям заголовков (например, «Turnover (DB)», «Balance», «Description») и назначает текстовые элементы столбцам на основе их координаты X. Записи с датой (DD.MM.YYYY при x < 100) обозначают начало строки.

    CSV¶

    Текстовый формат с разделителями-запятыми. Парсер:

    1. Извлекает информацию о счёте из заголовочных строк (до первой строки данных)
    2. Обрабатывает поля в кавычках со встроенными запятыми (например, "1,220.09")
    3. Обрабатывает многострочные описания (строки, не начинающиеся с даты, добавляются к предыдущей строке)
    4. Автоматически переводит грузинские ключи заголовков на английский

    Как загрузить файл¶

    1. Перетаскивание — перетащите файл(ы) из файлового менеджера в зону загрузки
    2. Выбор через проводник — нажмите кнопку загрузки и выберите файлы

    Несколько файлов

    Вы можете загрузить несколько файлов одновременно. Приложение автоматически объединяет и дедуплицирует транзакции из разных файлов. Это работает для:

    • Нескольких месяцев одного и того же счёта
    • Разных счетов (GEL + USD)
    • Смешанных форматов (часть XLSX, часть PDF)

    Определение валюты¶

    Приложение определяет валюту каждого файла по следующей цепочке приоритетов:

    1. Лист с информацией о счёте — поле Account Currency из заголовков XLSX/CSV
    2. Шаблон имени файла — определяет коды валют в именах файлов, например MYCREDO_GEL_STATEMENT_... или statement_USD.pdf
    3. По умолчанию — используется GEL

    Поддерживаемые шаблоны имён файлов:

    Шаблон Пример
    _GEL_ MYCREDO_GEL_STATEMENT_2025.xlsx
    .USD. statement.USD.pdf
    -EUR- export-EUR-jan.csv
    GEL.xlsx GEL.xlsx
    STATEMENT_USD STATEMENT_USD.pdf

    Дедупликация¶

    При добавлении файлов к существующему набору данных (через кнопку «+ Add Files») приложение предотвращает дублирование транзакций с помощью составного ключа:

    key = date | debit | credit | operation | currency | balance

    Добавляются только те транзакции, чей ключ ещё не существует. Это означает, что вы можете безопасно повторно загружать пересекающиеся файлы без появления дубликатов.

    Хранение данных¶

    Обработанные данные хранятся в localStorage браузера под ключом credo_statement_data. Это означает:

    • Данные сохраняются при обновлении страницы и перезапуске браузера
    • Данные привязаны к браузеру и домену (не передаются между устройствами)
    • Очистка данных браузера или нажатие «New File» удаляет всё

    Ограничения хранилища

    localStorage имеет ограничение ~5 МБ в большинстве браузеров. Для очень больших наборов данных (тысячи транзакций по множеству счетов) вы можете приблизиться к этому лимиту. Приложение корректно обрабатывает ошибки превышения квоты — если сохранение невозможно, оно продолжит работать из памяти.

    Работа офлайн¶

    После первой загрузки страницы приложение полностью работает офлайн. Чтобы проверить:

    1. Откройте приложение и загрузите его один раз
    2. Отключитесь от интернета
    3. Загрузите банковскую выписку
    4. Панель управления загрузится и будет работать нормально

    Единственная функция, требующая интернета, — получение обменных курсов для мультивалютных счетов (из API НБГ).
